项目内容
以 ABB AC500 PM556 为控制核心、力控组态为上位监控，实现「空气引入 → 点火降氧 → 冷却过滤 → 惰气收集」全流程自动化。在 Automation Builder（CODESYS 内核）中按监控 / 控制 / 执行三层规划 I/O（8DI / 6DO，扩展 AX561 模拟量 + DC562 数字量模块）；下位机以 LD（IEC 61131-3）单一 POU 循环扫描，经 Modbus TCP 与上位机通信。
本人职责
作为负责人独立完成硬件组态与软件设计：规划 I/O 点表与模块地址；编写 LD 顺序控制与条件连锁逻辑；经 COM_MOD_MAST 以 Modbus 写 WR 区驱动 ACS355 变频器分档调速（≈7.5 / 25 / 45 Hz）；搭建力控上位监控并与 PLC 做同址映射；负责整机联调与故障排查，交付可复用的排故清单。
技术要点
  • 联锁顺序：TON 延时强制「先点火后喷油」，避免炉膛先积油再点火；电机自锁 + 互锁防止同时启动。
  • 急停取常闭：断线即等于触发，断电、接触不良、按按钮都进入安全状态，属于故障导向安全（fail-safe）接法。
  • 传动通信：Modbus 写变频器频率给定寄存器，三档频率切换后读实际频率核对跟随情况。
  • 上位监控：力控画面与 PLC 变量同址映射，实现流程状态可视化与参数在线调参。
调试记录
  • 燃油泵跟着风机一起启——炉膛先积油再点火是爆燃风险。查 LD 发现泵和风机共用同一个启动条件，条件本身没写错，是「先后顺序」没约束住 → 把点火确认前置成泵的使能位，再补 TON 延时。
  • 上位画面数值不动，PLC 侧却在变——先怀疑通信断，但连接状态正常；比对地址发现整组变量是「整齐地偏了一段」而不是随机错 → 判为 Modbus 寄存器基址偏移，改同址映射后恢复。
  • 电磁阀通电不动作——DO 指示灯亮，万用表量到输出有电压、阀体却不动 → 装配方向接反，重装后正常。
项目成果
实现全流程自动化运行、参数在线调参与三档调速稳定切换；联调中独立定位并解决 5 类典型故障——下载失败（IP 网段）、燃油泵误启（补 TON + 点火前置）、变量不刷新（Modbus 地址偏移）、电磁阀方向接反、通信超时（扫描周期需 ≥20 ms），排查耗时从最初的数小时压缩到约 30 分钟，整机联调与演示通过。
复盘
这一版只做到软件联锁。真实燃烧设备还需要硬件层面的互锁（火焰检测器确认着火后才允许开油阀，信号直接串在油阀回路、不走程序）、氧含量在线检测联动、以及故障时的安全停机顺序（先断油、再停风、最后报警）。课设里我只验证了「能不能跑起来」，没验证「跑飞了怎么办」，这是事后才意识到的短板。

在力控组态中搭建两水罐液位监控系统：罐体按液位驱动填充动画，水泵、调节阀、出水阀做开关状态显示，管道做流动属性；自建数据变量并编写控制脚本，使液位在规定区间循环变化、阀泵按联锁条件动作；越限报警、历史与实时趋势、开机 / 主界面 / 报警 / 趋势四画面互跳，并与 S7-1500（PLCSIM）通信联调。
本人职责
独立完成变量规划与命名、画面与动画组态、控制脚本编写、报警与趋势配置、画面跳转与权限设置，以及力控与 PLC 的通信建立、变量地址映射和联调排故。
技术要点
  • 联锁按与逻辑串接：调节阀需「罐 1 达高位且罐 2 低于低位」同时成立才允许打开，任一条件消失即关断，防溢罐也防干抽；水泵、出水阀各按单点液位限位启停。
  • 高低限分开设定形成回差（滞环），避免阈值附近反复动作。
  • 报警与趋势分开组态，趋势按固定采样周期记录，不跟着动画刷新走。
调试记录
  • 画面数值全是 0——PLCSIM 侧程序在跑，力控读不到。逐项核对通道配置，发现连接压根没建立 → 补 IP 与机架 / 槽位后恢复。
  • 连上了但数值不刷新——连接正常、地址也对，最后落在数据类型上：组态侧按字读、PLC 侧是另一个宽度 → 改数据类型与偏移。
  • 调节阀在阈值附近反复开关——高限和低限用同一个值，边界上必然抖动 → 高低限分开设定形成回差。
项目成果
动画、脚本、报警、趋势、多画面跳转五类必做项全部实现并演示通过；力控与 PLCSIM 通信正常，可读写变量并联动画面。调试中定位并解决两类问题：变量地址与数据类型不匹配导致数值不刷新、通信未连上导致画面全零。

项目内容
工厂 110/10 kV 降压变电站电气一次部分设计。按任务书负荷资料统计得出有功缺额约 40.89 MW，据此确定电压等级与主接线方案：110 kV 侧双母线（含母联）、10 kV 侧单母线分段，两条 110 kV 架空进线，两台 S11-M-12500/110 主变分列运行。主变参数 110/10.5 kV、±4×2.5% 有载调压、Uk%=10.5、YNd11。用标幺值法（Sd=100 MVA、Ud=10.5 kV、Id=5.5 kA）算各短路点电流，按额定参数、动稳定、热稳定三项逐台校验设备，最后用 AutoCAD 绘制 A1 主接线图并出设备明细表。
本人职责
全程参与并用 AutoCAD 绘制 A1 主接线图；参与电压等级与主接线方案比选、主变容量与台数论证、断路器与隔离开关及互感器母线的选型；承担负荷统计与短路电流的部分计算，配合完成继电保护整定。
技术要点
  • 台数由「能不能顶」定，不由「够不够用」定：剩余负荷折算 11.11 MVA，单台 12.5 MVA 本来够用；定两台是因为任一台检修或故障时另一台要能带起全部剩余负荷——11.11 < 12.5 刚好够，容量也就此卡在 12.5 MVA 这档。
  • 开断能力按各点短路水平分档：110 kV 进线断路器取 40 kA，母联与主变间隔取同系列 31.5 kA；10 kV 侧 20 kA 开断对 Ik≈5 kA、峰值 50 kA 对 ish≈12.75 kA 各留约 4 倍。同一电压等级不同位置配不同档，不搞一刀切。
  • 两条供电路径分开算：系统供（110 kV 经主变）短路点 K₂ 得 Ik≈5 kA、ish≈12.75 kA、Sk≈90.9 MVA；发电厂直供 10 kV 那条 Ik=0.55 kA、ish=1.44 kA。两者的工作电流也不同（611 A 与 917 A），选型各按各的路径配。
  • 软母线看机械强度，硬母线看动稳定：110 kV 户外选 LGJ-400/35 钢芯铝绞线，载流量 710 A 对 66 A 是十倍余量，真正的约束是短路电动力下的机械强度；10 kV 柜内选 LMY-100×10 矩形硬铝排，取大截面主因是相邻母排间的电动力与电流平方成正比，排间距和厚度不够会变形。
校验与取舍
  • 主变先按单台考虑，算完才发现没有备用——剩余负荷 11.11 MVA 落在一台 12.5 MVA 之内，看似够用；但检修窗口一开就得全站停电 → 改两台分列运行，容量不用往上加档，2×12.5 MVA 正好卡住。
  • 10 kV 断路器额定电流按 630 A 选，回头核出 917 A——发电厂直供那条路径的负荷比剩余负荷大，630 A 覆盖不住 → 该路径改 1250 A 档。同一个 10 kV 等级出现 630 A / 1250 A 两个档，是两条路径负荷不同造成的，不是选型随意。
  • 母联从 40 kA 降到 31.5 kA——母联点的短路电流比进线端低一档（电流经线路阻抗与进线断路器后已被削弱），照进线那档选等于多花钱 → 按短路水平选，这是这次设计里最像工程取舍的一处。

项目内容
基于 STM32F103C8T6 搭建覆盖 3 间仓库的安全监测系统，集成 LM35 温度、DHT11 温湿度、MQ-2 烟雾、红外入侵共 12 路传感，按「采集—主控—执行」三层组织，配 0.96 寸 OLED（I2C）多页显示、蜂鸣器 + LED 声光报警与消防联动；基于标准外设库（SPL）在 Keil MDK 开发，主循环状态机周期约 300 ms。
本人职责
独立完成 12 路传感接入与驱动编写；实现温度 >90℃ 与烟雾双重判定、ADC 多通道扫描 + 均值滤波、红外电压跌落入侵检测；编写 OLED 多页显示与报警状态机；经 J-Link 烧录固件，负责 Proteus 仿真与实物联调。
传感与接口
  • LM35 / MQ-2：模拟量，走 ADC 多通道扫描；MQ-2 输出随预热时间漂移，上电后先做基线校准。
  • DHT11：单总线，微秒级时序，读取时关中断避免被打断，且采样降频、不是每圈都读。
  • 红外入侵：电平 / 电压跌落判定，属开关量输入。
  • OLED 0.96"：I2C 总线上只有这一个器件，不存在同地址冲突。
调试记录
  • 单点温度判据下误报不断——环境温度一波动就报警 → 改成温度 + 烟雾双重判定，误报归零；90℃ 是实验条件下能稳定复现火警的「确认」值，不是随便取的。
  • MQ-2 上电后读数一路往上爬——传感器预热期输出漂移，拿来判定必然误报 → 上电先做基线校准；滤波值只上显示，报警判定走原始值，免得滤波器把报警拖慢。
  • 串口能通但速率整体偏——编译能过、程序也跑，是对照 datasheet 查时钟树和分频才发现的 → 用示波器实测反推真实波特率。
项目成果
Proteus 仿真与实物联调均稳定运行，实现 3 间仓库温度 / 湿度 / 烟雾 / 入侵集中监视与声光报警；采用温度 + 烟雾双重判定后误报降至 0 次（单点温度判据下环境温度波动即频繁误报），报警响应 <1 s，连续运行 8 小时以上无死机 / 丢数。
指标口径
「0 次误报」指连续 8 小时空仓运行、无真实异常条件下的统计，不是产线长期运行数据；90℃ 是实验条件下能稳定复现火警的「确认」阈值，真实仓库应做两级判定（如 45–60℃ 预警、90℃ 确认）。均值滤波只用于显示与趋势，报警判定走原始值，避免滤波器把报警拖慢。
复盘
驱动框架与初始化代码借助大模型起手，但配置逐条对照 datasheet 核对——大模型给小众外设的参数经常是猜的，典型如时钟树和分频配错：编译能过、程序也能跑，但串口波特率整体偏、ADC 采样率与预期差一截，只能靠示波器实测反推。另外这套是轮询状态机，够用但不严格，要保证实时性应上中断或 DMA + 环形缓冲。

项目内容
以一级倒立摆（小车 + 单杆）为对象，先建立非线性动力学模型，在竖直平衡点附近线性化得到状态空间方程；在 Simulink / Simscape 里搭非线性被控对象，在同一初始偏角、同一扰动量下分别接入 LQR、串级 PID 双闭环与 BP 神经网络 PID 三种控制器，做时域仿真并横向对比。
本人职责
小组共同完成建模与线性化、三种控制器的设计与整定、Simulink 仿真搭建、数据整理与曲线对比；课设报告按指导书章节结构编写，我是小组成员之一。
控制方案
  • LQR：取角度、角速度、位移、速度四个状态量，靠 Q / R 权重在「立得稳」与「回得快」之间取舍，解 Riccati 方程拿反馈增益。
  • 串级 PID 双闭环：外环按位置偏差给出姿态参考，内环按角度偏差出力，两层都限幅。结构最直观、最好向别人解释，代价是参数要分层试凑，两个环相互牵制。
  • BP 神经网络 PID：用反向传播在线调整 PID 三个参数，让增益随误差自己变。难点不在网络结构，而在样本、初值与学习率——学习率给大了，起摆那一瞬间就发散。
调试记录
  • 算出来的增益代进 Simulink 完全不复现——两边转动惯量的口径不一致，模型不同源 → 统一参数后一次就对上了；这一处来回调了十几轮。
  • 低增益时摆立住了，小车却一路跑偏——只看角度曲线会误判成「已经稳了」→ 补上行程判定才暴露出这种失效。
对比与结论
对比口径统一为超调量、调节时间、稳态误差与扰动后的恢复过程，而不是只看「能不能立住」。三种方案各有取舍：LQR 有明确的二次型指标、整定路径清楚，但对模型精度最敏感；串级 PID 不依赖精确模型、现场好调，但要人肉试参；BP 神经网络 PID 在线适应性最强，可解释性与稳定性论证最弱。具体数值以课设报告里的实测曲线为准。
复盘
踩得最深的一个坑是线性化模型与非线性仿真必须同源：我先按极点判据搜出一组增益，代进 Simulink 却完全不复现，最后发现是两边转动惯量的取值不一致。另一个反直觉的地方是，低增益的失效形态不是「摆先倒」，而是摆勉强立住、小车一路跑偏越界——所以补了行程判定，否则这种失效光看角度曲线根本看不出来。

Weather Studio — a zero-build static PWA plus a Capacitor Android shell. The web layer is plain ES modules (no framework, no bundler, no image assets) and the same source ships as an installable offline PWA or an APK with four hand-written native plugins. Four switchable weather providers expose capability flags so the UI decides what to render instead of special-casing a vendor; air quality is a four-level degradation chain where every number carries a provenance badge. Themes are single JSON files applied at runtime and validated offline for contrast. Engineering is evidence-first: 110 in-browser assertions measuring real DOM/computed styles, 96 mutation-forcing entries proving each assertion can actually turn red, and five second-scale gates in CI; on a real Huawei handset cold start measured 524–573 ms with 0.19% jank on the long list. MIT, v1.2 released.
技术要点
  • 零构建：Web 层是原生 ES Module，不用框架、不用打包器、不依赖图片资源；同一份源码既能发成可离线安装的 PWA，也能封成 APK。
  • 四家数据源：每家通过能力标志声明自己支持什么，界面按标志决定渲染什么，而不是给每家写一套特判。
  • 空气质量降级链：四级降级，每一档的数字都带出处徽章——数据从哪一级降下来、依据是什么，看得见。
  • 主题即 JSON：一份 JSON 描述整套主题，运行期导入即生效，并做离线对比度验收。
质量证据
  • 110 条真 DOM 浏览器断言：测的是真实 DOM 与计算样式，不是快照、不是桩。
  • 96 处变异逐条逼红：每条断言都要能被变异打红——打不红的断言等于没写。
  • 五条秒级闸门进 CI：把关卡做成秒级反馈，而不是等整条流水线跑完才知道。
  • 华为真机实测：冷启动 524–573 ms，长列表 jank 0.19%。
成果
MIT 开源，已发布 v1.2（含 APK）；网页层与安卓壳同源，主题、断言与闸门脚本都在仓库里可查。
复盘
这个项目让我把「做完了」换成「证明了」：功能多不多不重要，能不能指出「哪一条证据挂了它就红」才重要。96 处变异逼红这件事看着多余，但它把「断言会不会其实什么都没测」这个问题挡在了外面——没被变异打红过的断言，我不敢当成证据。

    项目内容
    四档数控恒流源，把需求拆成电源 / 控制 / 检测 / 恒流四个模块。按键经 74LS192N 计数生成 0–3 档编码，74LS04 反相 + 4066BD 模拟开关选通不同参考支路，送入运放与功率管完成 V/I 转换输出恒流；档位经 7483N + 7447N 译码驱动数码管显示。
    本人职责
    独立完成方案设计与硬件实现：四模块划分与电路设计；用 Multisim 逐档仿真验证四档逻辑与切换过程；推进硬件联调，确认选通、显示与恒流三者联动无误；排查虚焊与器件极性错误。
    恒流原理
    采样电阻上的压降与基准电压比较，误差经运放放大后调功率管，把电流稳在设定值。4066 只切参考电压支路、不在主电流回路里——运放输入阻抗高，支路几乎不走电流，几十欧的导通电阻只影响分压比，标定一次即可补掉；若把它串进主回路，误差就会直接叠加到负载上。精度主要由采样电阻精度与温漂、运放失调电压、功率管温升漂移决定，数字部分只决定档位。
    调试记录
    • 某一档切过去没有输出——按键计数和译码显示都正常，问题在选通支路 → 逐个量 4066 的使能与支路接点，定位到虚焊。
    • 切换瞬间电流有跳变——选通支路一变、恒流环要重新建立，这一版只做了逻辑上的先断后通，没做软切换。
    项目成果
    稳定输出 1 / 50 / 100 / 150 mA 四档恒流，档位切换与实时显示正常；Multisim 四档仿真与硬件联调均验证通过。
    复盘
    四档切换时选通支路变化、环路要重新建立，我这一版只在逻辑上做了先断后通，没有软切换，所以切换瞬间会有跳变——加大输出电容、做渐变给定是可以改进的方向。另外用 74 系列搭是课程要求，练的是计数器 / 译码器 / 模拟开关怎么配合；现在回头看，MCU + DAC 会简单得多、精度也更好调。

    项目内容
    搭建交直流电机控制主回路与控制回路并完成通电调试；基于西门子 S7-1500 实现交流电动机位置控制，读取编码器反馈构成位置闭环。
    本人职责
    作为 3 名小组成员之一，承担交直流电机主 / 控回路接线与通电调试；参与 S7-1500 位置控制调试，逐项完成定位、正反转、调速与制动；参与搭建编码器检测电路，实现转速与转向测量。
    闭环与整定
    用增量式编码器，A/B 相计数并判向，Z 相做零点校正。整定顺序是先把比例增益加到接近临界振荡再回退，然后加积分消稳态误差；出现振荡就降增益或加滤波。这里要说明：参数是小组一起试的，我承担的是接线与通电调试那一段，不是我一个人定的。
    调试记录
    • 转速测得出来、方向判不对——增量式编码器要 A/B 两相同时计数才能辨向，只接一相只能测速；Z 相还得做零点校正，否则累计误差回不了零。
    • 比例增益给大就振荡——先把比例加到接近临界振荡再回退，然后补积分消稳态误差，振荡时降增益或加滤波。参数是小组一起试的。
    项目成果
    完成交直流电机主 / 控 2 套回路的接线与通电调试；位置闭环的定位、正反转、调速、制动共 4 项功能全部达标；编码器测速与辨向结果与设定值一致；与 2 名组员分工协作、按节点完成整机联调。
    安全与实操
    通电前先验电、确认急停可用；测电压用并联、单手操作、档位先高后低；测通断前断电并给电容放电。正反转靠两台接触器换相序，电气互锁是把对方常闭辅助触点串在自己线圈回路里，防止相间短路。
